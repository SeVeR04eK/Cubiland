## 2. Purpose and Format

User stories describe product needs from the perspective of a user or system actor. They are not implementation instructions.

Standard format:

> As a [type of user], I want [capability], so that [benefit].

Priority labels:
- **Must:** required for the agreed MVP or essential product integrity.
- **Should:** important, but can be scheduled after Must items.
- **Could:** useful if capacity and scope allow.
- **TBD:** priority or release assignment has not been confirmed.

Priorities below are provisional and must be reconciled with the approved Phase 1 prioritisation.

## 15. Story Notes

- Priority and release assignment are provisional.
- A story marked TBD requires a product decision before implementation planning.
- Stories should be split into smaller stories when they cannot be delivered and tested as one coherent increment.
- Technical tasks should be derived from approved stories and requirements, not substituted for user needs.
- Acceptance criteria are maintained separately in `ACCEPTANCE_CRITERIA.md`.
